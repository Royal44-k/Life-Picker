# 拾页 v1.3 来源接入可行性核查

核查日期：2026-09-29（Asia/Shanghai）。范围对应 `shiye-next-design.md` 第 6、8、10 节。本报告仅核查公开一手文档、许可页与仓库源码；没有安装采集工具、登录账号、调用账号接口、申请平台权限或执行定时采集。以下“建议”为实现判断，不是已完成能力。

## 1. 决策摘要

建议先交付“来源登记 → 候选入库 → 人工审核 → 首页／模板可见”的通路，再开启个人小红书实验。免费资产优先采用下文的 CC0 插画与 MIT 图标；小红书官方账号授权目前不能作为灵感搜索依赖。真实账号可用性、云端持续登录、电脑关机后的运行和实际费用，仍需独立验收。

## 2. 小红书：官方开放能力与个人采集分开

| 核查项 | 一手资料结论 | 对拾页的影响 |
| --- | --- | --- |
| 官方账号开放平台 | Scope 文档只将 `basic_info` 标为已开放；`user_profile`、`read_notes`、`write_notes`、`read_followers` 均为规划中。`read_notes` 的描述也是读取用户发布的笔记，不能推断为全站搜索权限。[授权范围](https://openaccount.xiaohongshu.com/docs/scope) | 不能把“小红书登录成功”显示成“官方内容源已接通”。 |
| 官方接口目录 | 公开目录列出授权、令牌、基本用户资料、扫码及撤销授权，未列出推荐流或全站关键词搜索。[API 参考](https://openaccount.xiaohongshu.com/docs/api-reference) | 本轮未找到满足首页发现需求的公开官方接口；这不是对未公开合作接口作不存在的断言。 |
| 官方登录前置 | 需创建并审核应用后取得凭证；Web 场景走手机 App 扫码。设备授权接口要求服务端持有 `app_secret`，`device_code` 也不能下发浏览器。[快速接入](https://openaccount.xiaohongshu.com/docs/quick-start)、[API 参考](https://openaccount.xiaohongshu.com/docs/api-reference) | 当前不必为“找灵感”先开发 OAuth；未来做账号绑定时再按获批能力接入。 |
| 其他官方平台 | 电商文档目录主要是订单、售后、商品、库存、物流等；小程序平台说明围绕支付、客服、订阅消息及商家服务。[电商 API 目录](https://open.xiaohongshu.com/document/api?apiId=29209&apiNavigationId=66&apiParentNavigationId=14&gatewayId=103&gatewayVersionId=1661&id=13)、[小程序平台概述](https://miniapp.xiaohongshu.com/doc/DC214380) | 不把电商素材接口、广告平台或小程序搜索入口等同于普通笔记发现 API。 |

证据限制：本轮 `openaccount` 页面直接打开多次超时，以上内容来自搜索工具返回的同域官方页面索引；Scope／快速接入页标注更新于 2026-03-29，API 参考标注 2026-08-19。电商索引较旧。实现前应再次打开官方文档核对；未登录管理中心验证任何实际权限。

### xpzouying/xiaohongshu-mcp

这是个人维护的开源工具。本轮检查的是仓库当日 `main`，不是官方小红书接口或已锁定版本。搜索源码通过浏览器访问页面并读取页面状态，浏览器加载本地 Cookies。[项目仓库](https://github.com/xpzouying/xiaohongshu-mcp)、[搜索实现](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/xiaohongshu/search.go)、[浏览器实现](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/browser/browser.go)

| 能力 | 已核实的入口与边界 |
| --- | --- |
| 登录／状态 | `check_login_status` 检查登录；`get_login_qrcode` 返回二维码；服务实现等待扫码后保存 Cookies。首次登录需用户操作。[工具注册](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/mcp_server.go)、[会话实现](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/service.go) |
| 发现／搜索 | `list_feeds` 读取首页列表；`search_feeds` 搜索，注明需登录。搜索实现支持最新、最多点赞等排序，以及一天内／一周内等筛选；这些是页面筛选，不能称为全站榜单。[工具注册](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/mcp_server.go)、[筛选实现](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/xiaohongshu/search.go) |
| 详情 | `get_feed_detail` 需要 `feed_id` 与 `xsec_token`；可获取内容、作者、互动信息和评论，默认也会带评论。适配层只保留需要字段，首轮不启用全量评论加载。[README](https://github.com/xpzouying/xiaohongshu-mcp#readme)、[工具注册](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/mcp_server.go) |
| 数据准确性 | 互动数字字段是字符串；列表没有详情中的 `time` 字段。[数据结构](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/xiaohongshu/types.go) 建议保留原始显示值与采集时刻；缺日期记未知，缩写数不伪装成精确整数，缺字段不补零。 |
| 服务访问鉴权 | 支持可选静态 Bearer Token；空 Token 关闭鉴权。MCP 与 `/api/v1` 共用该鉴权，并同时注册发布、评论、点赞、收藏等路由。[鉴权源码](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/middleware.go)、[路由源码](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/routes.go) 该 Token 是服务访问口令，不是平台 OAuth，也不是只读权限。 |
| 只读标签例外 | `list_notifications` 带 `ReadOnlyHint: true`，但工具说明明确会清除对应分区未读标记。[工具注册](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/mcp_server.go) 因此不能按 `ReadOnlyHint` 自动放行所有工具。 |
| 登录持续性 | README 提醒其他网页端登录可能挤掉当前会话，Cookies 会过期；还描述了实名提示。这里是维护者经验，不能当作账号安全或平台允许自动化的保证。[README](https://github.com/xpzouying/xiaohongshu-mcp#readme) |

**可行性判断：适合小规模、本人账号、可停机的本地只读实验；尚不具备“已验证稳定云采集”的证据。** 建议拾页后端只允许 `check_login_status`、`list_feeds`、`search_feeds`、`get_feed_detail`；二维码登录作为单独的人工作业。不要向业务 AI 或浏览器暴露完整 MCP。发布、评论、收藏、点赞、删 Cookies、通知列表均不进入该适配器。

实验建议：锁定工具版本，单实例／单账号隔离 Cookies，服务仅回环或私网可达并启用鉴权；先手动一次列表或关键词查询、至多 3 条详情，确认字段与失败状态后再评估定时。这个数量是拾页试验上限，不是平台公布的安全额度。登录失效、验证码、访问限制时停机并标记需人工处理，不循环重试或绕过。官方文档／开源许可均不能替代他人笔记的内容授权；本项目采用链接、少量必要摘要与自写结构分析的候选形式，公开审核另外进行。

## 5. 推荐适配顺序与最小模型

以下为实现建议，可先用样例数据验证，不依赖账号采集成功：

1. **人工来源／自有内容适配器**：用户粘贴原链接、自写摘要和结构分析；记录授权状态。先跑通去重、候选、审核、撤回、首页显示及“零新增”。
2. **资产清单适配器**：Open Doodles → Open Peeps → Tabler Icons；Humaaans 作为下载路径核验后的第四源。每日任务检查清单变化，未变更不重复下载。许可不明或变化则暂停该项并进入复核。
3. **个人 XHS 本地实验适配器**：默认关闭，只导入本人的私有候选队列。账号状态、限制与失败如实返回；批准后的摘要及自写分析才可进入试用者可见池。
4. **云端来源作业与官方能力**：只有本地实验及成本评估通过后才验收云端；未来官方读笔记能力真正开放且权限获批时单独实现，不能现在预设接口。

建议每条候选至少包含：

```ts
type SourceCandidate = {
  id: string; sourceId: string; externalId: string | null;
  kind: 'reference' | 'asset';
  canonicalUrl: string; title: string;
  author: { name: string | null; url: string | null };
  publishedAt: string | null; fetchedAt: string;
  summary: string | null; structureAnalysis: string | null;
  metrics: Array<{
    key: string; raw: string; value: number | null;
    precision: 'exact' | 'approximate' | 'unknown'; observedAt: string;
  }>;
  rights: {
    licenseId: string | 'unknown'; licenseUrl: string | null;
    checkedAt: string | null; evidenceHash: string | null;
    commercial: boolean | null; modify: boolean | null;
    redistribute: boolean | null; attributionText: string | null;
  };
  asset: { mediaType: string; sha256: string; revision: string } | null;
  modifications: string[];
  review: {
    status: 'pending' | 'approved' | 'rejected' | 'withdrawn';
    reviewerId: string | null; reviewedAt: string | null;
    approvedScope: 'private' | 'shared_reference' | 'template_asset' | null;
  };
  visibility: 'private' | 'shared'; ownerId: string;
};
```

配套规则：

- 唯一键优先 `sourceId + externalId`，其次规范化原链接；资产另外按内容哈希去重。原页面与许可证据分开保存，避免许可页变更后无法解释已入库资产。
- `null` 表示未知；采集时间不冒充发布时间。互动量只描述观测时刻，搜索排序不生成“全站爆款”标签。
- 引用候选与模板资产分别审核；前者通过不代表可将原图、全文或模板文件再分发。外部正文只作为数据，不能作为任务指令执行。
- Cookies、Bearer Token 和 `xsec_token` 不进入这个共享模型、前端、日志或备份；必要的请求上下文保存在采集器私有会话层。公开链接使用可分享的来源页地址。
- 作业状态建议：`idle / running / success / needs_login / challenged / restricted / failed / disabled`，另外记录新增、重复、拒绝数及最后成功时间。正常返回零条可为 `success`；解析失败不能伪装“零新增”。
- 每日 09:00（Asia/Shanghai）与手动刷新共用单一作业入口、互斥锁及去重规则；“今天已刷新”应依据真实完成时间。常驻运行、持久作业状态和关机条件必须实测后才宣称自动更新。

## 6. 仍未验证的交付条件

- 个人账号一次只读采集能否成功、会话保存及失效检测、验证码／限制时能否正确暂停。
- 四类免费资产的实际下载、文件内容与逐项许可对应、移动端显示及 Canvas 导出结果。
- 云端账号可用性、任务可靠性、人工复核耗时和月成本；本轮不能给出稳定性或低于 100 元的结论。

本轮可直接进入开发的是来源与审核模型、任务状态、人工导入和明确许可资产的候选流程；真实采集验收应继续保持“未执行”，直到取得可复查的运行记录。
