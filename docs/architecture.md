# 架构与核心资产

基线 v1.10.0。沿用 React / TypeScript / Vite + Canvas + IndexedDB，Node 本机服务提供 AI、外部来源与 FFmpeg 编码。没有改成原生 iOS 工程。

~~~mermaid
flowchart LR
  A["文字 / Markdown / 照片"] --> B["随心记 · 原话 · 共享素材"]
  B --> C["确认公开副本 / 作品"]
  C --> D["章节与分镜 · 单页编辑"]
  D --> E["尺寸测量与分页"]
  E --> F["同一 Canvas 预览 / PNG / ZIP"]
  B --> G["周月年回忆 · 确认快照"]
  G --> F
  G --> H["Node + FFmpeg → MP4"]
  I["用户主动 AI 请求"] --> J["服务端密钥 · 用量预算"]
  J --> K["建议预览与确认"]
  K --> C
  L["外部参考 / 设计候选"] --> M["来源夹 · 人工审核"]
  M --> C
~~~

## 模块地图

| 模块 | 资产与责任 |
| --- | --- |

## 数据保存位置

| 数据 | 保存位置 | 是否上传本仓库 |
| --- | --- | --- |

| 版本源码、说明与演示 | Git、archives/、docs/、public/ | 是 |

## 关键不变量

1. 原文不静默截断；6 / 9 页属于软目标，内容容量按实际尺寸处理。
2. 单页编辑后的确认版本同时驱动预览和导出。
3. AI 只接收用户选择的内容，返回结果先检查，旧请求不能覆盖新编辑。
4. 私人原记录与公开作品副本分开；照片删除受引用保护。
5. 备份恢复校验格式、身份和引用，发生错误时保留原数据。
6. 外部时间与数值未知时保持未知，来源审核后展示，候选不等于可用模板。
7. 小红书遇到登录失效、验证、限制或不可识别页面停止；不读取隐藏状态、Cookie 或内部签名接口。
8. GitHub 仅查询固定官方端点并核验实际 MIT 许可，不执行下载的项目代码。

## AI 与视觉资产

文案、聊天、分镜、单页编辑、选题、视觉建议与回忆串联提示词及响应校验位于 server 对应模块。用量统一由 usage 模块记录。规则排版和小拾基础动画无需模型。

小拾原创形象、装扮和动画集中在 src/journal/Xiaoshi.tsx、companion.css、companion.ts、companion-profile.ts；开放主题固定来源与改编说明在 src/studio/open-designs.ts，完整第三方许可在 public/licenses/。
